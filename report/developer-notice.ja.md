**件名：【作業のお願い】`<リポジトリ名>` の git 履歴を書き換えます（`<日付>` `<開始時刻>`〜`<終了時刻>`）**

`<リポジトリ名>` の git の履歴に、認証情報が含まれていることがわかりました。認証情報はすでに無効にしています。そのうえで、履歴から削除するために、次の日時に履歴を書き換えます。

## 1. 凍結期間：`<日付>` `<開始時刻>`〜`<終了時刻>`

- この間は、`<リポジトリ名>` に **push しないでください**。PR のマージ、ブランチの作成と削除、タグの作成もしないでください。
- 作業中は、ブランチ保護を一時的に外します。

## 2. 凍結の前までにお願いしたいこと

- **未 push のコミットを確かめてください。**

  ```bash
  git log --branches --not --remotes --oneline
  ```

- 必要な作業は、できれば凍結の前に push して PR にしてください。
- オープン中の PR は、できるだけ凍結の前にマージするかクローズしてください。

## 3. 書き換えの後にお願いしたいこと（必須）

書き換えた後は、すべてのコミットの ID（SHA）が変わります。**古いクローンはそのまま使えません。**

1. **新しくクローンしてください。**

   ```bash
   git clone <リポジトリの URL> <新しいディレクトリ>
   ```

2. **未 push の作業がある場合は、新しいクローンに載せ直してください。**

   ```bash
   cd <新しいディレクトリ>
   # 古いクローンのブランチを一時的な名前で取り込む
   git fetch <古いクローンのパス> "+refs/heads/<ブランチ>:refs/rescue/<ブランチ>"
   # 新しい基点からブランチを作り、未 push のコミットだけを載せ直す
   git switch -c <ブランチ> origin/<元にしたブランチ>
   git cherry-pick <古いクローンでの origin/<元にしたブランチ> の SHA>..refs/rescue/<ブランチ>
   # 一時的な参照を消し、古いオブジェクトを片付ける
   git update-ref -d refs/rescue/<ブランチ>
   git reflog expire --expire=now --all && git gc --prune=now
   ```

   - `<古いクローンでの origin/<元にしたブランチ> の SHA>` は、古いクローンで `git rev-parse origin/<元にしたブランチ>` を実行して調べてください（**古いクローンで `git fetch` する前に**調べてください）。
   - 載せ直したコミットに認証情報が含まれていないか、push の前に確かめてください。

3. **古いクローンを削除してください。** 古いクローン、stash、worktree、別のマシンにあるコピーも含めます。

4. **完了したら `<連絡先>` に知らせてください。**

## 4. やってはいけないこと

- 古いクローンから `git push`（とくに `--force`）すること。消した認証情報が戻ってしまいます。
- 古いクローンで `git pull` や `git merge` をすること。「refusing to merge unrelated histories」と表示されたら、そこで止めてください。`--allow-unrelated-histories` は使わないでください。
- 古いブランチを、新しい履歴のブランチにマージすること。実際にはない差分（同じ内容のコミットの重複）が大量に出ます。

## 5. 変わること

- コミットの ID（SHA）がすべて変わります。旧 ID と新 ID の対応表は `<保存場所>` にあります。
- コミットの署名は消えます。署名付きのタグは、署名のない注釈付きタグになります。
- オープン中の PR は、そのまま新しい履歴で表示されます。ただし、行へのコメントは「outdated」になることがあります。
- ブランチごとのコミット数、件名、マージの構造は変わりません。
